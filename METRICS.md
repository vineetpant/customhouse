## False positives by sink class

This is the table that should decide enforcement mode per class: a class that never produces a false positive can bear a hard block, and one that produces them constantly cannot.

| Sink class | Benign attempts | Blocked | Recommended mode |
| --- | --- | --- | --- |
| `payment_transfer` | 1 | 0 | `deny` |
| `external_send` | 7 | 3 | `require_approval` |
| `data_egress` | 2 | 1 | `require_approval` |

### Recommended configuration

```toml
[flow]
payment_transfer = "deny"
external_send = "require_approval"
```
